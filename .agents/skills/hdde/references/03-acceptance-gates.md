# HDDE｜阶段验收门禁

## 1. 通用硬门禁

以下任意一项失败，禁止返回 `PASS_AND_FROZEN`：

1. 受保护成果丢失、覆盖、回滚、遗漏或被重新实现；
2. 本阶段唯一目标未完成；
3. 必要真实运行未执行或失败；
4. 直接相关测试未执行或失败；
5. 验收门禁没有真实证据；
6. 修改范围明显扩张；
7. 未经授权执行 Git、提交、推送、合并、Tag 或发布；
8. staging 非空；
9. 报告与实际工作区不一致；
10. 使用临时回退、Mock 或伪成功掩盖正式机制失败；
11. 原图、用户正式文件或历史有效数据受损；
12. 当前代码仍需要同阶段后续补丁指令。

## 2. 目录治理

至少证明：

- 正式目录来源唯一；
- 默认目录或用户设置读取正确；
- 目录不可用时明确失败；
- 不回退项目临时目录；
- 不自动改写用户设置；
- 可写目录能真实写入；
- 应用重启后状态正确；
- 用户正式文件不受损；
- 页面不显示内部临时路径。

## 3. 历史目录迁移与清理

至少证明：

- 迁移对象经过归属识别；
- 正式数据与测试数据区分正确；
- 迁移前有安全预检；
- 冲突处理明确；
- 迁移后文件数量、路径和可读性正确；
- 原数据保留或删除符合任务卡；
- 无法确认的数据没有被删除；
- 受保护成果完整。

## 4. 前端

至少证明：

- 直接相关前端构建成功；
- 真实页面可加载；
- 关键状态、按钮和导航符合要求；
- 禁用状态有真实原因；
- 错误状态提供可理解提示；
- 控制台无本阶段新增错误；
- 用户可见内容不暴露内部路径和工程代号。

## 5. 后端与 API

至少证明：

- 直接相关测试通过；
- 真实接口响应符合合同；
- 错误路径返回真实业务状态；
- 不通过 HTTP 200、默认值或假数据掩盖失败；
- 调用链中的正式目录、配置和状态一致。

## 6. 图片处理

至少证明：

- 原图未被覆盖；
- 输出可完整解码；
- 格式、尺寸和比例符合目标；
- 不裁切、不拉伸、不错误补边；
- Alpha 与颜色关系安全；
- 中文、Logo、人物和产品结构无实质性失真；
- 输出进入允许正式目录；
- 失败时不产生伪成功文件或结果。

## 7. 日志

至少证明：

- 真实相关事件或故障被触发；
- 日志包含阶段、原因或影响中的有效信息；
- 日志等级合理；
- 关键目录与写入错误可定位；
- 不制造大量噪声；
- 不泄露不应用户可见的内部信息。

## 8. 版本

至少证明：

- 权威版本源明确；
- 前端、后端、系统设置、接口与构建一致；
- 测试没有继续依赖过期版本；
- 用户可见品牌名正确；
- `VisualMasterPro` 不进入用户可见产品名称。

## 9. PASS_AND_FROZEN

必须同时满足：

- 真实问题解决；
- 硬门禁全部通过；
- 证据与当前代码一致；
- 无阻断性遗留；
- 无需继续同阶段修复；
- 可以进入下一阶段规划。
