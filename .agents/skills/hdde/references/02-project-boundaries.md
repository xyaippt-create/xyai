# HDDE｜永久产品与工程边界

## 1. 正式名称

正式用户可见名称：

- 影界
- 影界 HDDE
- HDDE
- HD Delivery Engine
- 高清交付引擎

`VisualMasterPro` 只能作为历史项目名、内部工程名或旧开发代号。

不得出现在：

- 用户可见软件名称；
- 页面品牌；
- 系统设置产品信息；
- 浏览器标题；
- 安装包名称；
- 正式对外材料。

## 2. 正式目录唯一来源

产品采用单一正式根目录机制。

默认正式根目录建议为：

`D:\影界文件`

只有用户通过系统设置手动修改，正式目录才允许变化。

正式目录不可用、不可写或校验失败时：

- 不得静默回退项目 `tmp`；
- 不得回退 `runtime_data`；
- 不得回退测试目录；
- 不得自动改写用户设置；
- 必须明确返回未就绪；
- 必须暂停依赖该目录的处理任务；
- 必须提供可理解的设置修复入口或错误提示。

不得向用户暴露内部临时路径。

## 3. 图片压缩输出目录

图片压缩输出目录不得硬编码为不可修改路径。

默认可为：

`D:\影界文件\图片压缩输出`

必须：

- 复用现有本地目录选择和设置机制；
- 经过路径规范化；
- 经过可写性与安全校验；
- 支持用户修改默认输出目录；
- 支持当前任务选择输出位置；
- 失败时明确阻断；
- 不覆盖原图。

## 4. 原图与正式文件保护

任何图片处理、迁移、清理和输出任务都必须：

- 保护原图；
- 不覆盖用户正式文件；
- 不删除无法确认归属的目录；
- 不损坏历史有效数据；
- 不把测试文件当正式文件迁移；
- 不用伪成功掩盖失败。

历史目录迁移和安全清理必须先完成：

1. 数据归属识别；
2. 有效性判断；
3. 迁移目标确认；
4. 冲突处理；
5. 真实迁移验证；
6. 原数据保留或安全清理判断。

## 5. 最高画质原则

高质量但不能失真。

任何增强、压缩、缩放或适配不得实质性改变：

- 原图结构；
- 中文笔画；
- Logo；
- 人物五官和皮肤；
- 产品包装；
- 品牌色；
- 材质关系；
- 光影逻辑；
- 背景虚化；
- 原始设计意图。

输出至少必须：

- 完整解码；
- 尺寸和比例符合目标；
- 不裁切、不拉伸、不错误补边；
- 不破坏 Alpha；
- 不覆盖原图；
- 进入允许的正式目录。

出现实质性失真时，不得报告画质通过或建议直接交付。

## 6. 结果真实性

禁止：

- Mock 4K 结果；
- Mock 正式文件路径；
- Mock 下载按钮；
- Mock 质量通过结论；
- 伪造已完成的 OCR、AI 颜色恢复或局部修整能力；
- 返回不存在的输出；
- 以 HTTP 200 掩盖业务失败；
- 用静态页面状态代替真实处理结果。

所有用户可见结果必须对应真实后端状态、真实文件和真实能力。

## 7. 版本治理

产品版本必须有单一权威来源。

下列位置必须保持一致或从同一来源读取：

- 系统设置；
- 应用信息；
- 后端接口；
- 前端显示；
- 构建信息；
- 必要测试。

不得在多个位置独立硬编码并长期漂移。

## 8. 用户可见命名

涉及水印或类似标记的能力，用户可见位置不得直接使用容易产生版权误解的名称，例如：

- 去水印；
- 消除水印；
- 水印处理输出。

优先使用：

- 标记修整；
- 标记区域修整；
- 修整结果；
- 其他中性、真实、可解释的名称。

相关能力只面向用户自有、客户授权或内部项目素材。

第一版只开发图片标记修整；视频能力必须另行立项并完成独立 PoC 后再决定。

## 9. 日志与诊断

日志唯一目的：

- 定位真实运行问题；
- 还原故障过程；
- 判断影响范围；
- 支持快速修复。

每条正式日志至少应回答一项：

- 发生了什么；
- 发生在哪个阶段；
- 为什么失败；
- 影响了什么；
- 下一步如何定位。

禁止：

- 无价值状态重复；
- 不能帮助排障的埋点；
- 只为形式完整写日志；
- 用复杂诊断中心替代真实功能；
- 向用户暴露敏感内部细节。

优先记录真实故障链：

- 启动；
- 配置；
- 正式目录；
- 后端异常；
- 图片处理关键阶段；
- 任务耗时；
- 写入失败；
- 用户可恢复动作。

## 10. 当前产品结构保护

在没有独立产品决策和正式阶段授权前：

- 不调整整体产品方向；
- 不重构一级导航；
- 不重新归并主要模块；
- 不启动全量 UI 重构；
- 不把后续视频能力并入当前图片基础功能；
- 不把未来能力写成已经存在。

新增能力必须先形成独立阶段任务卡。
