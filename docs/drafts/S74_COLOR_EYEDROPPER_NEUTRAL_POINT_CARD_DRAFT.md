## 第一部分　原则

### 1. 为什么做

S67（自动挑档）、S69-B（去灰 v3）、S71（除雾）三次失败的原因相同：**只看像素，分不清“有意的设计色调或浅色设计”和“偏色或灰雾”**。S69-A 已把测量器加固到可用，但建议档位只能封顶为“轻”，原因也是这个歧义。

这个歧义机器判断不了，人看一眼就知道。用户在图上点一下“这里本来应该是白（或灰）”，偏色的方向和幅度就由这个点直接确定，不需要再猜。

### 2. 服务的负责人目标

偏色图能被**修准**，而且结果可控、可解释；不在设计图上自作主张。

### 3. 原则

1. **用户点的是事实，不是建议**：吸管点给出的白点替代自动测量的白点；没有点时，挑档校色与现状逐字节一致。
2. **复用冻结结构**：四档（原图、轻、中、强）、渲染方式（按白点做色适应）、安全门禁、人脸保护、Alpha 保护、预览→选档→像素摘要校验→正式写入的链路全部沿用，只换白点来源。
3. **点错要拦住，不要硬修**：点到鲜艳颜色（不像白或灰）或过曝、纯黑的位置时，不生成预览，告诉用户原因，请他换一个位置。
4. **不重绘、不生成细节**：只做全图色适应，和现有挑档一样。
5. **范围收窄**：本卡只做挑档校色的白点。黑点（去灰）、参考图模式加吸管、批量套用均不在本卡范围。

### 2. 唯一目标

在挑档校色中加入“点选白点”：用户点一下图上应为白或灰的位置，四档预览按这个点校正。

### 3. 现状（读码确认，2026-11-18）

- `engine/color_correction/level_pick.py`：`analyze_level_pick` 测出 `cast["ab"]`（白点的 a\*b\*），`_cast_curve` 把它铺成各亮度上相同的曲线（L\*=100 固定为纯白），`_render_prepared` 按档位强度 0.4/0.7/1.0 做色适应。渲染前提是 `neutral["reliable"]` 为真且曲线非空。
- `backend/image_compression_api.py`：`POST /api/color-correction/level-preview` 只接受 `source_token`、`reference_source_token`、`client_context`；会话缓存测量结果（S69-E），`level-run` 复用缓存，缓存缺失时重新 `analyze_level_pick`，再与预览像素摘要比对。
- `src/ColorCorrectionPage.jsx`：挑档模式有当前档位大图预览和放大弹窗（`onZoom`）。

### 4. 做法（建议，可按代码事实修正）

**后端**
1. `level_pick.py` 新增白点采样：输入为相对坐标 `(x, y)`（0–1，相对原图宽高，含 EXIF 方向校正后的显示方向，执行时须核对预览与解码像素方向一致）。在原图上取以该点为中心的小块（半径约为长边的 0.4%，最少 3 像素），排除过曝（≥250）、过暗（≤5）和透明像素后，取线性 RGB 中位数作为白点。
2. 白点不合格时拒绝：有效像素过少（过曝或纯黑区）、白点彩度过高（初始阈值 C\* > 30，与现有 `NEUTRAL_MAX_CHROMA` 一致）。返回具体中文原因。
3. 合格时用白点的 a\*b\* 替代 `cast["ab"]`，构造同样的平铺曲线，渲染、安全门禁、人脸保护不变。分析记录增加 `neutral_source: "USER_POINT"` 与采样坐标、白点值；无点时记录不变。
4. 接口：`level-preview` 新增可选字段 `neutral_point: {x, y}`，与参考图互斥。会话保存该点；`level-run` 缓存缺失时按同一点重新分析，像素摘要校验保持不变。不新增接口，不新增 FinalAction。
5. 建议档位与提示：有白点时的建议档位见负责人裁定 Q2；测量说明改为“按你点选的位置校正：该处偏黄/偏蓝……”。

**前端**
6. 挑档模式增加“点选白点”按钮。进入后鼠标在原图大图（和放大弹窗）上变十字，点击后显示标记，并以该点重新生成四档预览。另有“取消白点”回到自动测量。
7. 点被拒时，用现有提示样式显示原因，不清空当前预览。
