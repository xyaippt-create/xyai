## 第一部分　原则

### 1. 为什么做

发灰（暗部抬起、整体像蒙了一层雾）是常见问题，但 S69-B 和 S71 两次都失败在同一点：只看像素，分不清“发灰”和“本来就浅、本来就柔和的设计”，自动估计还会估错雾色导致偏色。S71 结论记下的重启条件之一是“改为用户框选雾区或指定颜色”。

S74 已经证明“让用户指认”能消除这种歧义：用户点一处“这里本来应该是黑的”，暗部该压到多深就由这一点确定，不再让机器猜。

### 2. 服务的负责人目标

发灰图能被**看得见地变通透**，同时不碰本来就浅、本来就柔和的设计（不点就不改）。

### 3. 原则

1. **用户点的是事实**：黑点只来自用户点选；不点时一切与现状逐字节一致，自动测量的去灰路径（S69-B 判定 v2）不改。
2. **只压暗部，不动亮部**：按黑点把暗部压回去，亮部和白点基本不变；不做局部去雾、不估计雾色、不重建细节。
3. **能和白点一起用**：白点负责偏色，黑点负责发灰；两者可单独或同时使用，仍是原图、轻、中、强四档。
4. **点错要拦住**：点在不够暗的地方、已经是纯黑的地方、透明区域时，不生成预览，说明原因。
5. **安全门禁不放松**：沿用剪切增长（压暗不能把暗部压成死黑一片）、人脸肤色、Alpha 等门禁。
6. **整组一致**：在批量挑档（S75）中，代表图的黑点校正与白点校正一起套用到整组。

### 2. 唯一目标

在挑档校色中加入“点选黑点”：用户点一处本来应该是黑的地方，四档预览按这一点把发灰的暗部压回去。

### 3. 现状（读码确认，2026-11-18）

- `level_pick.py` 已有去灰渲染：在 L\* 上做黑白点线性拉伸（`haze` 的 black / white / lift / headroom），参数由 `_estimate_haze` 自动估计；S69 实测该路径让 9 例发灰样本中 8 例变差，所以自动去灰从不建议，白点模式和整组套用都不做去灰。
- 白点（S74）走 `neutral_point` → `_analyze_user_point`；整组（S75）走 `transfer_level_pick_correction`，复用代表图的曲线。

### 4. 做法（建议，可按代码事实修正）

1. **采样**：与白点相同的小块采样（长边 0.4%，最少 3 像素），排除透明像素，取亮度中位数 L\*<sub>b</sub>。拒绝条件：L\*<sub>b</sub> > 40（不像本来应是黑的地方）、L\*<sub>b</sub> ≤ 4（已经是黑的，无需校正）、透明。
2. **校正**：在 L\* 上做单调曲线：L\*<sub>b</sub> 映射到 L\*<sub>b</sub> − 强度 × (L\*<sub>b</sub> − 6)，L\*=100 固定，中间平滑过渡；颜色按原彩度比例保持，不改色相。轻、中、强强度 0.4 / 0.7 / 1.0（与白点一致）。目标黑 L\*=6、拒绝阈值 40 和 4 在执行前固定。
3. **组合**：可与白点同时使用（先白点色适应、后黑点压暗）。接口 `level-preview` 增加可选 `black_point: {x, y}`；无黑点时代码路径不变。
4. **整组**：S75 的整组套用同时传递代表图的黑点曲线。
5. **页面**：白点按钮旁加“点选黑点”，同样是全屏选点、可重新点选或取消；测量说明显示“按你点选的黑点压暗暗部”。
