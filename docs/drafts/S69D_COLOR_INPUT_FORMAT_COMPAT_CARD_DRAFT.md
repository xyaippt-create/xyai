## 3. 已确认问题

颜色校正三种模式和批量共用同一个解码入口 `load_color_managed_source`，它只接受 8 位 RGB / RGBA：

- 调色板 PNG（压缩工具的常见输出）、灰度、灰度加透明、1/2/4 位 PNG 全部被拒，而这些转成 RGB(A) 是无损的。
- CMYK JPEG、16 位 PNG、不支持的色彩配置、多帧图被拒是合理的，但接口把所有原因都显示成同一句“图片的格式或色彩信息不受支持”。

## 4. 范围与不可破坏边界

- 允许修改已冻结的色彩管理入口（Color Core V2 基础层）的解码部分，以及接口的错误提示。需负责人在确认本卡时一并授权。
- 调色板、灰度、灰度加透明、1/2/4 位 PNG，以及灰度 JPEG：先无损展开为 8 位 RGB(A)，再进入现有流程。
- CMYK、16 位、不支持的色彩配置、多帧、非 JPG/PNG：保持拒绝。
- 现有 RGB / RGBA 输入的解码结果、色彩配置校验、输出编码、三种模式的算法和页面布局不变。
- 成品格式规则不变：PNG 进 PNG 出，JPEG 进 JPEG 出，带 sRGB 色彩配置。调色板图的成品是 RGB(A) PNG，体积可能比原图大，需在报告中如实列出。
- 不改自动校色链的判定、S69-A 冻结的测量、S66 成果、正式目录与原图。
