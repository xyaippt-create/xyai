## 第一部分｜产品与架构决策（需随本稿一并批准）

### 1. 背景

- S63-AICOLOR-POC 已证明：对真正偏色的 AI 图，"中性锚定、分亮度色适应"修正明显、安全，可以直接交付（S01、S02、S09）。
- 系统无法可靠区分偏色和设计用色，所以自动判定的价值没有成立（`POC_VALUE_NOT_PROVEN`）。
- 负责人于 2026-10-28 决定：正式功能改为"**用户说修才修，修多少由用户挑**"。

### 2. 决策内容

1. 颜色校正页新增第三种模式"**挑档校色**"，与现有的"自动校色""参考图校色"并列。现有两种模式的行为与合同都保持不变。
2. **流程**：
   - 上传一张图后，系统生成"原图 / 轻 / 中 / 强"四档预览，并给出测量提示（偏色方向与偏色量；可能是设计色调时明确提示"建议原图"）。
   - 用户选定一档后，系统才生成正式结果。选"原图"时不生成新文件。
3. **交付权限**：用户选定即视为人工确认。结果复用现有的人工确认交付语义（与现有 `HUMAN_CONFIRMED_REVIEW` 同级），不新增第四种 `FinalAction`。
4. **修正内容**：沿用 S63 冻结的修正方法与保护——肤色保护、柔和收顶与收底、分段估计收紧、暗部外推。不再引入新的算法。
5. **适用范围**：面向 AI 生成图。真实照片仍建议用自动校色，页面上给出说明，但不强制。
6. **授权范围**：批准本稿，即授权以下改动：
   - 为该模式新增必要的 API 字段与端点；
   - 修改颜色校正页的交互；
   - 在 `docs/contracts/` 补一份"挑档校色"合同补充。

   D57 合同正文、Color Core V2 冻结记录、正式目录与 Settings 不在授权范围内。

## 第二部分｜S64-A 任务卡：挑档校色后端与接口

调用 `hdde` Skill 执行以下单阶段任务。

### 1. 项目基线

- 项目目录：`D:\Codex\04_Visual-Master-Pro`
- 当前分支：`codex/image-processing-routing-v1`
- 预期 HEAD：`aa0dd93`（以执行时的实时状态为准，冲突时报告）
- 产品版本：`0.6.1-dev`（本阶段不修改）
- `STAGING_EMPTY` 预期：YES

### 2. 本阶段唯一目标

把 S63 已验证的三档修正接入正式颜色模块与 API。提供两个能力：
- 生成四档预览；
- 按用户所选档位生成正式 Result。

正式 Result 必须走现有的 Task、Result、Delivery 与 `输出\颜色校正` 合同。

### 3. 已确认问题

- **用户影响**：现在的自动校色对 AI 图几乎都保持原图，用户看不到修正。
- **证据**：
  - S63 报告中，正式链 15/15 保持原图；
  - 候选的三档在几何、裁切、肤色、对照这几项门禁上全部通过。
- **实现参考**：`tools/experiments/s63_aicolor_poc.py`，只是参考，执行时须按正式代码规范重写，不得直接 import 实验脚本。
- **未确认事项**：
  - 四档预览存在哪里、如何清理，须复用现有的预览与 token 机制，不得落到项目 tmp；
  - 4K 以上大图的耗时。

### 4. 不可破坏边界

- **必须保留**：自动校色与参考图校色的行为和测试结果、D3 门禁、`FinalAction` 枚举、正式目录、Settings、输出中心、智能交付、已冻结的成果，以及原图不被覆盖。
- **不做**：页面改动（属于 S64-B）、批量挑档、版本号变更。
- **禁止**：Git 写操作，以及 Mock、临时回退、伪成功。

### 5. 结果门禁

1. 用新的接口跑通 S63 的 15 张样本：
   - 四档预览与 S63 的冻结结果逐像素一致，或平均 ΔE00 ≤ 0.5（不一致时说明原因）；
   - 4K 以内的单张图，四档预览 ≤ 5 秒。
2. 选择轻、中、强任一档后，生成的正式 Result 须满足：
   - 文件真实、可解码，带 sRGB ICC，SHA 与记录一致；
   - 进入输出中心，交付资格为人工确认。
   - 选"原图"时不生成新文件，并有明确记录。
3. 所选档位与预览一致：正式 Result 的像素与用户看到的那一档预览一致。服务重启后，选择不能被篡改、错配，也不能复用过期预览。
4. 现有颜色测试、输出中心测试与前端测试全部通过，自动校色与参考图校色的行为不变。
5. 原图 SHA 不变；正式目录只新增用户选定的结果文件。
6. 补齐"挑档校色"合同补充文档，并更新 changelog 与当前状态文档。
