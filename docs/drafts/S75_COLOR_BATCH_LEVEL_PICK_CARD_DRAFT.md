## 第一部分　原则

### 1. 为什么做

批量颜色校正现在只有自动校色，而自动校色几乎不改图（S67、S69 结论）。挑档校色和 S74 白点能把一张图修准，但只能一张张处理。同一次拍摄或同一批生成的图通常光线一致、偏色一致，一张修准了，整组就该能按同样的量修。

### 2. 服务的负责人目标

偏色图能被**看得见地修准**，并且能**整组处理**，不必一张张挑。

### 3. 原则

1. **一张定档，整组同量**：用户在一张代表图上看四档预览（可点白点）并选定一档；整组每张图都按代表图测得的同一个校正量和同一档强度处理，不再逐张猜测。
2. **每张各自过安全门禁**：剪切增长、人脸肤色、Alpha 等门禁逐张检查；没通过的那张保留原图并写明原因，不影响其他图。
3. **没看过的图要复核**：代表图是用户亲眼选的，按人工确认处理；其余图用户没看过，结果进入处理中心“待复核”，确认后才能交付。
4. **复用现有链路**：四档、渲染、白点、安全门禁沿用挑档校色；排队、进度、处理中心、输出目录、复核沿用现有批量校色。不新增 FinalAction。
5. **不改单张**：单张挑档校色、参考图校色、自动校色和自动批量的行为不变。

### 2. 唯一目标

挑档校色支持一次选 2–20 张图：在代表图上选定一档（可点白点）后，整组按同一校正量生成结果。

### 3. 现状（读码确认，2026-11-18）

- 挑档校色只接受一张图（`selectedItems.slice(0, 1)`），`level-preview` / `level-run` 只处理单张，选定即人工确认。
- 自动批量：`POST /api/color-correction/batches`（2–20 张）建批次，后台 worker 逐张执行自动校色，候选结果为“待复核”，在处理中心确认后可交付。
- 挑档的校正量就是分析结果里的白点 `cast["ab"]`（S74 白点同样落在这里），渲染按档位强度 0.4/0.7/1.0 套用；人脸保护、安全门禁按每张图自己的像素计算。

### 4. 做法（建议，可按代码事实修正）

1. **引擎**：新增“按给定校正量分析”的入口：以代表图的白点 a\*b\* 构造同样的平铺曲线，人脸与安全门禁用目标图自己的像素。代表图本身的结果须与单张挑档逐字节一致。
2. **接口**：批量创建接受可选的挑档参数（代表图预览 `preview_id` 与所选档位）。后端从预览会话取出代表图的校正量，不接受前端直接传校正数值。批次复用现有排队、进度、处理中心与输出目录；代表图结果为人工确认，其余为待复核；没通过安全门禁的保留原图并写原因。
3. **页面**：挑档模式允许选多张；默认第一张为代表图，可改选另一张。生成代表图四档预览（白点可用），按钮显示“按‘X’档处理整组（N 张）”，提交后进入处理中心查看进度。只选一张时与现状完全一致。
