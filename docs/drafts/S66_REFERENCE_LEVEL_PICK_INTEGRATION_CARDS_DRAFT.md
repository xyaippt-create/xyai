## 第一部分｜产品与架构决策（需随本稿一并批准）

### 1. 背景

- S65-REFCOLOR-POC 的候选 R3（低饱和像素在对数色度空间对齐）已证明价值：
  - 有标准答案组：强档 21/24 组把色差缩小 ≥ 60%；
  - 同系列组：经代判复核，3/4 有一档明显优于现有参考图校色，并且无伤害。
- 现有参考图校色对 AI 图基本无效：有标准答案组中 17/24 组保持原图，其余只缩小 3%–25%。

### 2. 需要负责人选择的一项（执行方建议 A）

- **A（建议）：用新流程升级"参考图校色"。** 页签名称不变。页面改为：选目标图 + 参考图 → 四档预览 → 用户选档 → 生成结果。旧的 `/api/color-correction/reference-run` 后端原样保留，但页面不再调用，这样历史任务和结果照常显示，旧测试不受影响。
- B：新流程作为第四个页签"参考图挑档"，旧的参考图校色保留不变。

### 3. 决策内容（不论选 A 还是 B）

1. **流程**：
   - 系统测出"目标图相对参考图偏多少"（偏黄、偏蓝、偏绿的方向和比例），生成"原图 / 轻 / 中 / 强"四档；
   - 用户选定后才生成正式结果；选"原图"不生成新文件。
2. **交付语义**：与 S64 一致。用户选定即为人工确认，复用 `REVIEW_REQUIRED` + `REVIEW_CANDIDATE` + `confirmed` + `HUMAN_CONFIRMED_REVIEW`，不新增 FinalAction。结果中额外记录参考图的身份（SHA）和测得的偏移量。
3. **算法**：冻结 S65 的 R3 方法与常数（对齐范围、分段、偏离回退、通道增益、亮度保持），同时复用 S64 的肤色保护、柔和收顶与收底、安全检查。R2（明暗匹配）不接入。
4. **提示**：页面明确说明"结果会采用参考图的白，请选同一系列、同一光线的参考图"。测得的偏移太小时提示"两张图色调已接近"；参考图没有可用的中性区域时，提示"这张参考图不适合用来校色"，此时各档不可选。
5. **授权范围**：批准本稿即授权以下改动：
   - 为这一流程扩展 API 字段与端点；
   - 修改颜色校正页；
   - 更新 `docs/contracts/HDDE_COLOR_LEVEL_PICK_SUPPLEMENT_V1.md`（新增参考图一节）；
   - S66-B 重建正式 dist。

   不授权改动：D57 合同正文、Color Core V2、旧 `reference-run` 后端、正式目录、Settings、版本号。

### 4. 与正在进行的 4K 工作的协调（两个阶段都适用）

- 4K 优化在同一仓库、同一分支并行进行。本工作不读写任何 4K 相关文件，例如 `engine/image_processing_routing/four_k_v1.py`、4K 页面和 4K 模型。
- **修改共享文件前**，比如 `backend/image_compression_api.py`、`src/*.jsx`，先用 `git diff` 确认该文件没有 4K 一方未提交的改动。如果有，暂停并报告，不覆盖、不合并别人的改动。
- **重建 dist（S66-B）前**须征得负责人同意，避免与 4K 一方的页面改动互相覆盖；旧 dist 先完整备份。
- 不提交、不暂存，也不修改别人的未提交改动。
