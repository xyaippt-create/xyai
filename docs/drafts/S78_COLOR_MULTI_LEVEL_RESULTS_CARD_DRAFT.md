## 2. 唯一目标

单张挑档校色在一组四档预览上，可以一次生成多个档位的成品（例如“中”和“强”各一张），不必重新生成预览。

## 3. 已确认问题（读码确认）

`/api/color-correction/level-run` 生成一个结果后即把预览会话标为已用（`used_by_task_id`）并删除预览文件，再选别的档位会报“这组预览已经生成过结果，请重新生成预览”。4K 图重新生成预览约 5 秒，用户想对比两档成品时只能重复等待。

## 4. 做法（建议，可按代码事实修正）

1. 页面：单张挑档时档位可多选（原图除外）；按钮显示“生成所选 N 档”。只选一档时流程与现状完全一致。
2. 后端：一次请求按所选档位各生成一个成品，每档仍从原图重新渲染并与该档预览逐像素核对，用户看过的每档都按人工确认处理。复用现有颜色批次（排队、进度、处理中心、输出目录）承载多档结果，不新增接口家族、不新增 FinalAction。
3. 多档生成后进入处理中心查看这一组结果；单档仍进入统一结果页。

## 5. 范围与不可破坏边界

- 只改：挑档预览与运行/批次创建中的多档部分、颜色校正页挑档模式、处理中心对该批次的必要显示、直接相关测试。
- 单档挑档、白点、整组挑档（S75，仍为一组一档）、参考图、自动校色的行为与输出不变。
- 不改文件命名规则（`engine/output/filename_policy.py` 有他人未提交改动）。

## 6. 验收门禁

1. 一组预览一次生成 2–3 档，每档成品与该档预览逐像素一致；原图哈希不变；同一组预览同一档不重复生成。
2. 只选一档时，行为、结果与接口返回与现状一致；现有颜色、挑档、参考图、批量的接口与前端测试全部通过。
3. 多档结果在处理中心显示正确档位，均为已确认、可交付；任一档未通过安全检查则不可选。
4. 4K 图生成两档的总耗时不超过两次单档生成之和。
5. 隔离浏览器实测：一张图生成“中”“强”两档，处理中心看到两张成品，截图存证。
