## 第一部分｜《AI生成图偏色修正（可选强度）》原则变更稿

### 1. 变更原因

2026-10-27 扫描证据如下：
- 正式颜色链对 9 张 AI 样图 9/9 判为保持原图。
- 9 月真实使用 18 次，14 次保持原图、3 次进入复核。
- 最强一档自动色温只让 b\* 从 19 变到 18，肉眼看不出。

根因是现行 D57 合同以"恢复真实颜色"为目标，要求 GT 参考和 240 张盲测，并把明亮、暗调、暖调画面一律当作"颜色意图"保护起来。AI 生成图没有"真实颜色"可以对照，所以在现行规则下永远证据不足。

### 2. 新原则

1. **适用范围**：只适用于用户声明为 AI 生成的图片。真实照片继续执行 D57 商业颜色恢复合同，不受本原则影响。
2. **目标**：AI 图出现偏黄、偏蓝或发灰时，自动给出看得出的修正。
3. **修正方向只朝"中性、通透"**：
   - 偏色：把画面中应为中性的白、灰、黑拉回中性；
   - 发灰：恢复黑白场和正常对比；
   - 不做风格化调色、滤镜、氛围创造或美颜。
4. **多档可选，用户裁决**：
   - 每张图输出"原图 / 轻 / 中 / 强"四个选项并排对比，由用户挑选。
   - 用户是最终裁判。自动交付权限不再依赖 GT 参考和 240 张盲测，改为"用户选中即交付"。
5. **按偏色量缩放强度**：各档强度是对实测偏色量的比例修正，不是固定步长。
   - 本来不偏的图，各档变化都很小；
   - 偏得越多，修正越多。
6. **"颜色意图"不再一票否决**：高调、暗调、暖调、主色设计等判断，只用来降低推荐档位并在界面提示，不再阻止生成候选。
7. **硬保护（任何一档都必须满足）**：
   - 尺寸、方向、构图、Alpha 不变；
   - 不新增明显裁切、色带或光晕；
   - 肤色不得变灰、发青或泛红；
   - 文字和 Logo 形状不变。Logo 颜色随全局修正同步变化时，要量化并展示，由用户判断。
8. **技术边界**：
   - 本地确定性算法，不调用生成模型，不联网；
   - 在线性光空间做色适应，以及黑白场、对比度修正；
   - 不重绘，不补造细节。
9. **体验**：4K 以内的单张图，四档预览总耗时 ≤ 5 秒。

### 3. 与现有成果的关系

- D57 合同、Color Core V2 冻结记录、正式颜色链在本原则正式集成前**保持不变**。
- 参考图校色模式保持不变，可以和本原则并存。
- 本原则先经 PoC 证明有价值，再另开集成阶段。PoC 不进入正式运行链。

## 第二部分｜S63-AICOLOR-POC 任务卡

调用 `hdde` Skill 执行以下单阶段任务。

### 1. 项目基线

- 项目目录：`D:\Codex\04_Visual-Master-Pro`
- 当前分支：`codex/image-processing-routing-v1`
- 预期 HEAD：`aa0dd93`
- 产品版本：`0.6.1-dev`（不修改）
- `STAGING_EMPTY` 预期：YES
- 允许的终态：`REVIEW_PACKAGE_READY` / `POC_VALUE_NOT_PROVEN` / `BLOCKED`

### 2. 本阶段唯一目标

在隔离实验中证明：一个本地确定性的"中性锚定色适应 + 黑白场修正"候选，能为偏黄、偏蓝、发灰的 AI 图生成肉眼可辨、强度递增的"轻 / 中 / 强"三档结果，并交给产品负责人逐图挑选。

### 3. 已确认问题

- **用户影响**：AI 图偏色一直得不到可见修正。
- **证据**：
  - 正式链对 AI 样图 9/9 保持原图，场景意图判定为 HIGH；
  - 最强固定档只让 b\* 变化约 1；
  - 正式执行器限定为 `DETERMINISTIC_BASIC_CORRECTION`，与状态文档所写的 Color Core V2 不一致。
- **未确认事项**：
  - 偏色估计在大面积主色画面（如橙色流线、绿叶）上是否会误判；
  - Logo 颜色随全局修正变化后，用户能否接受。

### 4. 不可破坏边界

- **必须保留**：正式颜色链、D57 合同、Color Core V2 冻结记录、参考图模式、API、SSE、页面、Settings、正式目录、版本号、其他功能。
- **隔离位置**：
  - 只新增 `tools/experiments/` 下的执行器；
  - 输出写入 `artifacts/s63_aicolor_poc/`；
  - 不写 `D:\影界文件`。
- **样本**：
  - 来源为 `D:\HDDE样本\AIColor`，由用户放入，执行全程只读，并记录 SHA；
  - 至少 12 张：偏黄 ≥ 4、偏蓝 ≥ 3、发灰 ≥ 3、无需修正或故意冷暖的对照图 ≥ 2。
- **禁止**：Git 写操作、联网、生成模型、Mock、伪成功。

### 5. 结果门禁

1. **全部生成**：每张样本生成原图、轻、中、强四档。
   - 尺寸、方向、Alpha 逐像素不变，PNG/JPEG 都能完整解码；
   - 输出 sRGB ICC 与像素一致。
2. **看得出且递增**：在偏色、发灰样本上，中性区域的偏色量（平均 ΔE00 或 a\*b\* 偏离）随档位单调下降。
   - "中"档相对原图的平均 ΔE00 ≥ 3（可感知的起点）；
   - 数值是初始建议，由 PoC 校准，执行方不得自行放宽。
3. **对照不误伤**：对照样本"中"档的平均 ΔE00 ≤ 1.5（证明强度会随偏色量缩放）。
4. **安全**：
   - 高光和暗部裁切增量 ≤ 0.5%；
   - 无新增色带；
   - 肤色区域色相不跑出自然肤色范围；
   - 文字和 Logo 区域的颜色变化单独列出。
5. **性能**：4K 以内的单张图，三档合计耗时 ≤ 5 秒。
6. **复核包**：每张图有一张四档并排对比图和中性区域标注，附 `HUMAN_REVIEW.md` 逐图打分表（选哪一档、能否直接使用）。
7. **基线对照**：同一批样本用当前正式链再跑一遍并写入报告，证明新候选确有差异。

### 6. 报告合同

`STATUS`、`FILES_MODIFIED`、`IMPLEMENTED`、`VALIDATION`、`BLOCKER`、`PROTECTION`

人工复核由产品负责人完成。建议的价值成立标准（负责人确认后冻结）：
- 偏色、发灰样本中 ≥ 75% 有一档被判为"比原图好、可直接使用"；
- 任何一档都没有被判为"不安全"的伤害。

满足即为 `REVIEW_PACKAGE_READY` 后的正向结论，否则为 `POC_VALUE_NOT_PROVEN`。
