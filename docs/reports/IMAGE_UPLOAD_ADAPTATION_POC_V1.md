# 图片上传适配 PoC v1 技术报告

## 1. 任务定义

上传适配固定定义为：同时满足用户设定的最大宽度、最大高度和最大文件体积，并在约束内尽量保留最大的像素尺寸和最高可接受画质。

本次仅验证离线 PoC，不接入 UI、API、SSE、任务合同或正式 pipeline。只允许缩小、不允许放大；保持原始宽高比；不裁切、不拉伸、不补边；默认保持 PNG → PNG、JPEG → JPEG；不覆盖原图；每个尺寸和质量候选都直接从原图生成。

自动审核只能确认文件、解码、尺寸、字节数、宽高比、格式、原图 SHA、候选生成链路和 JPEG 有损标记。它不能确认视觉上没有裁切、拉伸或补边痕迹，也不能确认半透明 Alpha 边缘、中文、Logo、人物和产品材质没有视觉损伤。

## 4. 冻结策略与限制矩阵

正式运行前已冻结以下条件，运行后未调整：

- 尺寸顺序：`Smax`、95%、90%、85%、80%、75%、70%、65%、60%、55%、50%。
- 只保留不大于 `Smax` 且不低于原图 50% 的候选；重复像素尺寸去重。
- 尺寸取整：`floor(original_dimension × scale + 0.5)`。
- 50% 是本次 PoC 安全下限，不是正式产品阈值。
- JPEG 质量顺序：95、92、90、88、85、82、80；80 是本次 PoC 下限，不是正式产品质量下限。
- JPEG：Pillow 编码，`optimize=True`、`progressive=False`，保持源采样方式（无法识别时使用 2），每个质量候选从不可变原图像素独立编码。
- PNG：Pillow LANCZOS 缩小后，可独立执行已验证的 IDAT 同格式无损优化；不量化、不降色、不转换格式。

五类限制在每张样本上按同一公式生成：

| 场景 | 最大宽高 | 最大文件体积 | 目标 |
| --- | --- | --- | --- |
| A | 原始宽高 | 原始字节数 | 验证已达标时不处理 |
| B | 约原始 75% | `max(原始字节数×4, 1,000,000)` | 仅尺寸超限 |
| C | 原始宽高 | 原始字节数的 55%（最低 1024 B） | 仅体积超限 |
| D | 约原始 75% | 原始字节数的 30%（最低 1024 B） | 尺寸与体积同时超限 |
| E | 约原始 49% | 原始字节数的 10%（最低 512 B） | 验证低于 50% 时安全停止 |

`Smax` 始终是第一个尺寸候选。所有 311 个实际尝试均记录为 `generation_parent=immutable_source_pixels`、`prior_candidate_used=false`；不存在候选继续缩放或继续编码的链式处理。

## 6. 元数据、颜色与 Alpha

- `people_jpeg` 是固定样本中唯一实际带 ICC 的文件；其成功候选 ICC 内容哈希保持一致。
- 其余样本未带 ICC；输出继续保持未带 ICC。
- 固定样本均无 EXIF、EXIF Orientation、DPI 和 XMP；成功候选保持相同的存在状态。此次结果不能替代带 EXIF、DPI、XMP 正向样本的专项验证。
- PNG 保持 RGB/RGBA 模式；`real_alpha` 成功候选保持 RGBA 与 Alpha 通道。
- Alpha 自动门禁仅确认完全透明像素的 RGB 归零；半透明边缘是否出现黑边、白边或色边必须人工复核。
- JPEG 全部准确标记为有损重新编码；不得称为无损或视觉无损。

## 9. PoC问题回答

1. **能否同时满足尺寸和体积限制：** 在固定安全搜索范围内，B组8/8、C组8/8、D组7/8生成了满足全部技术限制的候选；不能把这解释为任意限制都可达成。
2. **PNG同格式路线边界：** 本次18个需要处理的PNG任务均技术达标，未使用量化、降色或格式转换；收益依赖内容与限制，且尺寸缩小会改变像素。
3. **JPEG搜索是否可控：** 质量和尺寸顺序固定、候选直接来自原图、搜索有明确下限；5个任务达标，1个人物D组任务安全停止。
4. **已达标时是否真正不处理：** A组8/8不重新编码、不创建正式候选副本。
5. **是否存在无法安全达标的真实样本：** 存在；`people_jpeg__D`在固定下限内不能满足限制，另有8个E组低于50%的限制被直接拒绝。
6. **安全停止是否准确：** 自动审核确认9个安全停止均未产出假正式候选。
7. **关键内容是否出现明显损伤：** 自动审核不能回答，必须保持 `VISUAL_REVIEW: PENDING`。
8. **是否具备进入任务合同设计的条件：** 技术结果已具备提交用户视觉复核的条件；视觉复核通过前不得进入任务合同设计。
9. **仍需评审的阈值：** 50%尺寸下限、JPEG质量80下限、极小中文可接受缩放、人物质量、产品材质和半透明Alpha边缘都需要盲测或人工评审。
10. **当前结论：** 技术审核通过，但阶段2尚未由用户视觉确认。
