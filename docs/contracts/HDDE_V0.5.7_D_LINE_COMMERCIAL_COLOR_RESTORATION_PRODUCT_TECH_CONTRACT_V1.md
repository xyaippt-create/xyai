## 2. 产品定位

影界 HDDE颜色恢复不是AI调色、风格创造或自动美化，而是把颜色和曝光存在明确问题、且原始信息仍可支持恢复的商业图片，恢复到可靠、自然、可交付状态。

```text
商业颜色恢复价值
= 真实颜色恢复
+ 可恢复曝光信息恢复
+ 人物与肤色可信
+ 产品与品牌颜色保护
+ 文字/Logo/结构/材质保持
+ 高精度安全退出
```

目标用户结果：

- 普通用户：照片恢复正常，不再明显偏黄、偏蓝、过暗或过亮。
- 设计师：通过门禁的素材不需要再次进行基础白平衡和曝光修复。
- 企业用户：获得`ACCEPT_CORRECTED`授权的图片可以直接进入既定数字商业交付流程。

产品成功不以“处理率高”“颜色更漂亮”“AI评分提高”或“文件成功生成”为依据。自动改动越多不代表产品越好；在证据不足时保留原图或进入复核是正确结果。

## 3. 明确非目标

V1不得开发成：

- 风格化调色、滤镜、电影感或氛围创造工具；
- 自动美颜、美白、磨皮、妆容或人物重绘工具；
- 产品重新着色、Logo换色或品牌设计生成工具；
- 单图HDR生成、过曝区域内容补全或暗部细节幻想工具；
- RAW开发器、印刷软打样系统或通用数字资产管理平台；
- 云端颜色处理服务、模型训练平台、颜色Dashboard或独立报告中心；
- HEIC、TIFF、PSD、PDF、CMYK或RAW的首期正式处理链。

不得用生成模型补造已经因饱和、量化、压缩或降噪而丢失的信息。只能恢复输入像素、可信参考或明确元数据仍能支持的内容。

## 4. V1输入与输出范围

### 4.1 首期输入

V1正式产品范围只包含：

- 单张JPEG；
- 单张PNG；
- 8-bit RGB/RGBA；
- 16-bit PNG只在颜色管理、候选执行和输出全链均通过原生精度验证后进入自动处理，否则保持明确复核或阻断；
- 有效嵌入ICC、可合理判定为sRGB的无ICC图片，以及能够被正式颜色管理层安全解释的输入。

以下输入不允许静默转换后继续自动交付：

- 损坏、冲突或无法解析的颜色Profile；
- 与像素编码事实冲突的Profile或元数据；
- 当前执行器不支持的位深、通道或格式；
- 动图、多帧或无法保证只处理正确帧的输入；
- 处理后需要缩小色域但没有已验证色域映射策略的输入。

### 4.2 输出事实

通过处理的输出必须：

- 不覆盖、不移动、不修改原图；
- 保持原始宽高、方向、构图和几何；
- 保持JPEG/PNG格式类别，除非后续合同明确授权格式变化；
- 保持Alpha逐像素事实和透明边缘；
- 使用与输出像素匹配的有效Profile，不得只机械回填与像素语义不匹配的旧ICC；
- 写入现有正式颜色校正目录合同，不回退仓库、tmp或测试目录；
- 继续复用现有Task、Result、Delivery和正式结果追溯。

## 5. 可恢复性边界

### 5.1 可以进入自动恢复候选

- 有独立中性色、可信肤色关系、拍摄参考或多区域一致证据的全局色偏；
- 可辨认且未完全丢失层次的全局曝光异常；
- 人物与背景亮度不均、但局部信息仍存在的曝光问题；
- 可由可信局部参考约束的有限混合光污染；
- 有官方品牌色、同场正确版本、色卡或其他独立颜色参考的产品色恢复；
- 能以有界确定性变换完成且通过全部保护门禁的图片。

### 5.2 必须保留原图或进入复核

- 无法区分现场暖/冷氛围与错误白平衡；
- 大面积主色可能被误判为光源色偏；
- 混合光区域边界、人物检测或保护区域不可靠；
- 没有独立参考却要求恢复某个未知品牌真值；
- 候选之间结论冲突或目标不唯一；
- 颜色改善与肤色、产品色、文字、Logo或材质保护发生冲突；
- 位深、ICC、Alpha或编码事实无法被当前链安全保持。

### 5.3 不可安全恢复

- 高光已经饱和且真实细节完全丢失；
- 暗部已经量化、压缩或降噪到没有可信信息；
- 原图颜色被不可逆处理且没有任何独立参考；
- 输入损坏或颜色编码无法被可靠解释；
- 任何恢复都只能依赖内容生成或主观猜测。

“不可安全恢复”是产品阻断原因，不新增第四个公共`FinalAction`。像素内容不可判定时映射为现有非交付`REVIEW_REQUIRED`并记录明确blocker；输入文件无效或无法解码时返回现有明确失败。不得为了新增概念修改公共接口合同。

## 6. 颜色真实性证据等级

Ground Truth按以下顺序使用，高等级证据优先，低等级证据不得覆盖高等级事实：

| 等级 | 证据 | 允许用途 |
| --- | --- | --- |
| `GT-A` | RAW正确渲染、灰卡、ColorChecker、同场多曝光或测量参考 | 白平衡、曝光和颜色恢复权威参考 |
| `GT-B` | 品牌官方Lab/sRGB/ICC色值及明确产品区域 | 品牌色目标和产品色差门禁 |
| `GT-C` | 同一场景、同一构图、可信正确白平衡或曝光版本 | 配对恢复参考 |
| `GT-D` | 两名独立专业修图人员处理并经第三方或产品负责人仲裁 | 缺少测量参考时的商业可用参考 |
| `GT-E` | 只有原图外观、单人意见或无独立参考 | 只能作为歧义/保护样本，不授权自动恢复 |

以下内容不能成为Ground Truth：

- 当前HDDE、Color Core V2或待评估V3自己的输出；
- 根据文件名、样本ID或预期结论生成的标签；
- 只因“更漂亮”而选中的结果；
- 自动指标最高但没有商业人工判断的候选；
- 在看到盲测结果后修改的参考、标签或阈值。

### 6.1 GT-D建立与盲评协议

本节是GT-D参考建立和V2/V3商业可用性盲评的唯一协议，不另设平行口径：

- 两名专业修图人员必须分别从冻结源图独立完成GT-D，不得看到HDDE、V2或V3输出，也不得在各自结果完成前讨论处理方法或结论；
- 两份独立结果完成后才允许由第三方或产品负责人处理分歧并形成仲裁记录；未经两份独立结果，不得直接以讨论后的共同版本充当GT-D；
- 盲评使用的源图、参考、候选集合、候选版本与文件哈希必须在评审前固定，候选以匿名编号呈现；
- V2、V3和控制项在每名评审者处独立随机排序，不得通过文件名、顺序或元数据暴露身份；
- 评审者不得看到算法名称、参数、预期标签、自动指标或预期分数；
- 至少两名评审者先独立给出`PASS`/`FAIL`及理由，只有独立结论不一致的项目才进入仲裁；
- 必须记录评审者数量、各自独立结论与理由、是否仲裁、仲裁结论和一致率；
- 盲评后如修改算法、参数、候选生成、门禁或与输出相关的实现，受影响的盲评证据立即失效，必须使用冻结后的新版本重新评审。

## 7. V3最小技术架构

V3采用“识别与决策可以智能化，像素执行必须确定、受限、可审计”的原则。

```text
输入与颜色管理
  -> D1 可恢复性与风险事实
  -> D2 有界多候选
  -> D3 非补偿式质量门禁
  -> D4 现有正式Result映射
```

### 7.1 输入与颜色管理

- 读取格式、位深、通道、EXIF方向、Alpha和ICC事实；
- 通过正式CMM把像素转换到冻结的线性或设备无关工作域；
- 工作域不得因方便而无依据压缩源色域；
- 颜色变换完成后转换到与输出Profile一致的编码；
- 具体CMM库和工作色域由`D57-COLOR-03`用往返误差、位深支持和桌面端可用性决定，不在本合同中预选大型颜色框架。

### 7.2 D1事实与授权

D1只负责判断：

- 是否存在可支持的色偏或曝光问题；
- 全局还是局部；
- 可恢复、歧义或不可安全恢复；
- 人物、产品、品牌、文字、Logo、材质、Alpha和色域风险；
- 是否允许生成自动候选、复核候选或直接保留原图。

同源的RGB、Lab、直方图和外观统计不能伪装成多个独立证据。肤色只用于相对恢复、保护和冲突判断，不允许以统一固定肤色目标授权全局改色。

### 7.3 D2有界候选

D2只允许最小必要候选：

- 全局白平衡或跨通道有界变换；
- 边缘保持的局部光照/颜色场；
- 保持色度事实的全局或分区亮度曲线；
- 人物、肤色、产品、品牌和强色区域保护；
- 原图候选作为永久基线。

V1不建设通用模型训练平台。优先复用现有检测与确定性变换；只有隔离证据证明现有能力不足且新模型具有明确净收益时，才允许另行授权一个有界模型候选任务。

### 7.4 D3唯一交付权限

D3继续作为唯一接受权威：

- `ACCEPT_CORRECTED`：全部硬门禁通过，候选获得自动交付资格；
- `ACCEPT_ORIGINAL`：原图更可靠或无需处理，不生成修改成品；
- `REVIEW_REQUIRED`：有候选但证据不足，或明确不可安全恢复，不具备自动交付资格。

任何平均分、AI评分、单一区域改善或视觉偏好都不能绕过硬门禁。

## 8. 商业质量门禁

### 8.1 P0硬失败

任一P0发生，候选不得进入`ACCEPT_CORRECTED`：

- 覆盖或修改原图；
- 宽高、方向、构图、边缘几何或Alpha改变；
- 中文、数字、小字、Logo形状或可读事实变化；
- 人物身份、五官、肤质事实或真实肤色关系异常；
- 产品结构、材质或有参考的品牌色超出冻结容差；
- 新增裁剪、黑白点丢失、明显色带、光晕或噪声放大；
- Profile与输出像素不匹配；
- 生成、猜测或重绘丢失信息；
- 正常暖光、正常冷光、强主色或无需处理控制样本被错误自动校正。

P0采用非补偿式聚合：其他指标改善不能抵消任何P0失败。

### 8.2 P1交付质量

通过P0后，商业可用还必须满足：

- 中性色和白平衡相对可信参考明显改善且没有反向色偏；
- 可恢复曝光信息增加，高光和阴影不新增破坏；
- 人物肤色经盲评为自然、真实、无蜡黄、泛红或灰白；
- 产品和品牌区域符合保护或参考目标；
- 整体结果无需再次进行基础白平衡或曝光调整；
- 处理结果相对原图和冻结V2具有实际商业净收益。

### 8.3 阶段验收目标

- 30张开发集只证明路线可行，不作为发布质量声明；
- 240张固定为30张开发、90张独立验证、120张盲测；
- 盲测中观察到的高风险P0错误自动交付必须为0；
- 人工直接使用率的唯一分母是冻结盲测中系统实际给出`ACCEPT_CORRECTED`的样本，必须同时报告`AUTO_ACCEPTED_N`、`HUMAN_DIRECT_USE_PASS_N`、`DIRECT_USE_POINT_RATE`和`DIRECT_USE_WILSON_95_CI`；
- `AUTO_ACCEPTED_N=0`时结论必须为`NOT_EVALUABLE`，不得以零失败、无自动交付或无分母判定`PASS`；
- `DIRECT_USE_POINT_RATE = HUMAN_DIRECT_USE_PASS_N / AUTO_ACCEPTED_N`，点估计必须不低于95%，并且Wilson 95%置信区间下限必须不低于90%；两项必须同时满足，不能互相补偿；
- V1必须分别报告白平衡恢复、曝光恢复、肤色恢复、产品与品牌色保护四条核心路线；每条路线都必须在盲测中获得独立、可归因的直接使用证据，不得以总体平均数替代缺失路线；
- `D57-COLOR-02`必须在查看验证集和盲测结果前，按核心路线冻结可纳入配额、最小可评估样本数、控制样本数、排除条件及统计口径；任一路线未达到冻结配额或最小可评估样本数时，该路线为`NOT_EVALUABLE`；
- 上述任何核心路线为`NOT_EVALUABLE`或未通过时，整体商业质量结论不得通过；
- 自动处理覆盖率不设置最低目标，避免以高处理率驱动误校正；
- 不设置最低自动覆盖率不得降低上述分母、样本充分性、置信区间、P0或分路线门禁；
- 240张只构成V1阶段证据，不等于证明所有商业图片的总体失误率；正式集成后仍需有界影子运行和真实反馈。

具体色差、曝光、纹理和Profile往返数值阈值只能在`D57-COLOR-01`指标有效、`D57-COLOR-02`参考样本成立后冻结，不允许根据当前污染基线预设。

## 11. 正式产品兼容边界

后续实现默认必须复用：

- 当前`D1 -> D2 -> D3`颜色决策与审计职责；
- 当前Task、Result、Delivery和共享Registry；
- 当前颜色校正页面、统一结果页、输出中心和智能交付；
